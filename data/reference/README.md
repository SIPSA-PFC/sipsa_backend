# Reference data

## neighborhoods.csv

One row per neighborhood, tying together how each source identifies it.
Generated by `scripts/build_reference_data.py` (see that file for the command);
committed so the ETL does not need the one-off dependencies.

| Column | Source |
|---|---|
| `name` | Canonical spelling, from `Dados_Modelagem.xlsx`, sheet *Casos de Dengue* |
| `code`, `district`, `egg_row` | `Rearranged_Data.mat`, MATLAB table `ReducedTable`: municipal code, health district, and the row of `EggIndice_Agregated` that holds this neighborhood's ovitrap data |
| `ibge_code`, `ibge_name` | IBGE 2010 neighborhood boundaries (*malha de bairros*) |
| `latitude`, `longitude` | Centroid of the IBGE 2010 polygon, computed in SIRGAS 2000 / UTM 25S and given in SIRGAS 2000 degrees |
| `coord_method` | `centroid`, or `representative_point` when the centroid falls outside the polygon (none currently) |

**Why `egg_row` matters:** the rows of `EggIndice_Agregated` are not in the same order as the
dengue sheet — none of the 36 positions match. The MATLAB code reorders them by name before use;
the ETL does the same through this column.

**Names** are matched on a key without accents, case or punctuation (`src/core/names.py`), plus an
alias for IBGE's spelling *Filipe Camarão*.
